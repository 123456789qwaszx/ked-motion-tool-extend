# 붙는 리그 · 여러 그림 · 불투명도 채널 — 이모지의 기반: 조사와 계획

> **다음 구조는 `PLAN-set.md`**(2026-11-10) — 이 문서의 이모지 작업을 범용(세트 · 연출)으로 다시 세운다. 여기 적힌 기능은 살고, 자리와 이름이 바뀐다.


소유자 요청(2026-11-10): 이모지 시스템을 모션 툴에서 완성해 쓴다. 런타임 쪽 설계(`ked-stage-runtime` `docs/PLAN_emoji.md`, 이 저장소에서는 못 읽는다)는
"캐릭터에 붙는 작은 리그 + 조각마다 노드 + 모션"이다. 이 문서는 **모션 툴이 그것을 저작·미리보기하려면 무엇이 있어야 하는가**만 다룬다.
`PLAN.md` §8이 미뤄 둔 "다중 스프라이트 리그"가 이것이다.

**결정(2026-11-10, 소유자): 불투명도는 모션 채널로 넣는다.** 흐려지며 사라지는 것이 정의 파일의 숫자로 가면 이모지 하나의 움직임이 두 곳으로 갈리고,
툴의 미리보기가 반쪽이 된다. 조각이 따로 흐려지는 것(꽃)은 조각별 커브가 있어야 만든다.

아직 열린 것: 로케이터를 기존 기준점 표(focus)로 할지 리그의 새 노드로 할지 · 좌우 반전이 어느 계층의 일인지(§5).

## 1. 조사 — 반입 코어와 덤프에서 확인한 것

| 사실 | 자리 | 뜻 |
|---|---|---|
| 코어는 **노드의 불투명도를 이미 안다** | `StageNodeClaimKind.CanvasAlpha` · `StageState.GetAlpha/SetAlpha` · `fade_in/out` 폴드 | 새 축이 아니다. 모션이 그 축에 닿는 길만 없다 |
| 불투명도는 `RectNodeState`에 없다 | `StageState._alphas`(노드 키 → 값, 없으면 1) | `MotionMath.StartOf(channel, RectNodeState)`로는 시작값을 못 읽는다 — 시그니처가 바뀌어야 한다 |
| 덤프가 불투명도를 받을 수 있는 노드를 적는다 | `RigSchemaNodeDto.hasCanvasGroup` · `canvasGroupAlpha` | 캐릭터 리그 26노드 중 3개. 채널을 놓을 수 있는 노드의 목록이 이미 있다 |
| 모션 채널 종류는 셋 | `MotionChannelKind { Position, Scale, Euler }` — `MotionMath.Neutral/Apply/ClaimFor/StartOf`가 종류로 갈린다 | 종류 하나를 더하는 자리가 코어에 다섯 곳쯤, 전부 `Motion/` 안이다 |
| 덤프는 **그림 노드를 표시하지 않는다** | `RigSchemaNodeDto`에 그림 표시가 없다. 캐릭터는 코어 상수 `PortraitSizingStageReduction.ImageNodeId` 하나 | 여러 그림을 그리려면 "어느 노드가 그림인가"를 덤프가 말해야 한다 |
| 코어는 리그를 다른 리그의 노드 밑에 세울 수 있다 | `RigSchemaLoader.AddRigTo(tree, rig, keyPrefix, attachParentKey)` | 툴도 이미 쓴다(오브젝트를 무대 뼈대의 Content 밑에 세울 때) |
| 툴은 오브젝트끼리의 부모·자식을 **만들었다가 지웠다** | `PLAN-scene.md` S6·S7 → "정리 2"(2026-10-28, 쓸 일이 없어서) | 이력에 있다. 월드 위치 보존까지 있었다 |
| 툴의 뷰포트는 오브젝트당 그림 한 장 | `ViewportView.DrawObject` · `SceneObject.Portrait` | 조각마다 그림을 주고 그려야 한다 |
| 툴의 모션 모델은 리그를 가리지 않는다 | 채널 = 노드 × 종류 × 성분, 검증은 rigKind의 노드 표 | **모션 모델은 손대지 않는다.** 그래프·도프 시트·클립·굽기·클립 안에서 고치기가 그대로 돈다 |
| 클립의 배역은 리그를 가리지 않는다 | `ClipRole.Rig` | "캐릭터 + 이모지"는 배역 둘인 클립이다 |

툴이 먼저 짓고, 아래 명세가 곧 런타임이 구현할 규약이다.** §2.1은 이 저장소의 코어 사본에 선반영했다(`src/Ked.Presentation.Core/vendoring.md`의 "선반영" 표 —
정본이 같은 모양으로 들어오면 사라지고, 다르게 들어오면 툴을 저쪽에 맞춘다).

### 2.1 불투명도 채널 — `motions/3`

| 항목 | 제안 | 까닭 |
|---|---|---|
| 종류 | `MotionChannelKind.Alpha` — 파일의 `"kind": "alpha"` | |
| 성분 | X 하나. Y·Z가 있으면 규칙 위반 | 위치의 Z가 null이어야 하는 것과 같은 꼴 |
| 값 | 0~1. 범위 밖 키는 규칙 위반(커브가 사이에서 넘치는 것은 재생이 0~1로 죈다) | |
| relative의 뜻 | **곱**(start × v), 중립값 1 | 배율과 같다. "지금 불투명도에서 흐려진다"가 된다 |
| absolute | v 그대로 | |
| 놓을 수 있는 노드 | 덤프에서 `hasCanvasGroup`인 노드만 — 아니면 로더가 거부 | 호스트가 쓸 CanvasGroup이 없다 |
| 시작값 | `StageState.GetAlpha(nodeKey)` — `StartOf`가 트리가 아니라 상태(또는 불투명도 값)를 받는 오버로드 | 불투명도는 `RectNodeState`에 없다 |
| 종점 | commit이면 `StageNodeClaim.CanvasAlpha(nodeKey, 끝값)` — `ClaimFor`에 한 줄 | 리듀서·장부·되감기가 `fade`와 같은 축으로 본다 |
| restore | 시작 불투명도로 돌아간다(다른 종류와 같다) | |
| 스키마 | `motions/3`. `/2`는 그대로 읽힌다(알파 채널이 없을 뿐) | 기존 파일·골든이 안 깨진다 |
| `fade_in/out`과의 겹침 | 같은 노드를 두 쓰는 사람이 잡는다 — 모션이 도는 동안은 모션이 이긴다고 못 박거나, 이모지 리그의 노드는 fade의 표적이 아니라고 둔다 | 소유권 규칙. 캐릭터의 fade 표적(`CharacterPortraitSprite_Root`)에 알파 모션을 놓을 일이 생기면 정해야 한다 |

### 2.2 덤프에 그림 노드 표시

`RigSchemaNodeDto`에 `hasImage`(그림을 그리는 노드인가) — 이모지 리그의 `Emoji_Part1…`이 여기 든다. 캐릭터 리그의 초상 노드도 같이 표시되면
툴의 "그림 노드 = 코어 상수 하나" 가정이 사라진다. 없으면 툴은 이름 규칙(`*_Part<N>`)으로 임시 판정한다.

### 2.3 이모지 리그를 덤프에

`rigKind: "emoji"` — 런타임 문서의 모양(`Emoji_Anchor › Emoji_Body › Emoji_Part1…`). 조각 수는 4(소유자: 꽃 넷보다 많은 이모지는 없다 — 늘려도 기존 모션은 안 깨진다).
불투명도를 조각마다 따로 주려면 **조각 노드마다 CanvasGroup**이 있어야 한다(묶음 전체는 `Emoji_Anchor`나 `Emoji_Body`).

### 2.5 이벤트 키 — `motions/3` (툴이 먼저 지었다, 코어 선반영)

| 항목 | 규약 |
|---|---|
| 자리 | 클립의 `"events": [ { "t": 0.3, "name": "emoji", "value": "땀" } ]` — 채널 배열 뒤, 없으면 안 적는다 |
| `t` | 초, 0 ≤ t ≤ 길이, 오름차순(같은 시각 허용) |
| `name` | `[a-z0-9_]+` — 호스트가 이 이름으로 받는 쪽을 고른다(`emoji`·`sfx`…). 어휘는 런타임이 정한다 |
| `value` | 자유 문자열, 없어도 된다(이모지 키·효과음 이름) |
| 재생 | 시각을 지나는 순간 호스트가 (슬롯, name, value)로 한 번 알린다 |
| 상태 | **아니다** — 리듀서는 접지 않고, Skip·Load·Rollback에서 다시 울리지 않는다(효과음과 같은 급) |
| 스키마 | 이벤트가 하나라도 있으면 `motions/3`(알파 채널과 같은 판) |
| 어휘(초안) | `emoji`(값 = 이모지 키) · `emoji_off` — 뜻은 §10. 툴이 먼저 지었다 |

### 2.6 끝없는 반복 — 재생하는 쪽의 인자

클립 블록의 반복(횟수)은 툴 안의 일이다(같은 모션 커맨드를 그만큼 부른 것). 지울 때까지 도는 반복(머무는 이모지의 punch)은 재생 인자로 요청한다:
`<<motion 슬롯 이름 [relative|absolute] [loop]>>` 또는 이모지 정의의 "머무는 동안 이 모션을 되풀이".

### 2.4 툴이 요청하지 않는 것

그림 넘기기(프레임 묶음)·되풀이·머무는 시간·어느 자리에 붙는가는 이모지 **정의**의 값으로 둔다(움직임이 아니다). 툴은 정의를 만들지 않는다 — 모션만 만든다(§6).

## 3. 툴의 설계

### 3.1 그림은 스킨에 — Spine의 슬롯·어태치먼트·스킨을 따른다(소유자 결정, 2026-11-10)

```
MotionDocument
  skins[]    { name: "꽃", rig: "emoji", parts: { "Emoji_Part1": "꽃-큰.png", "Emoji_Part2": "꽃-작은.png" } }
SceneObject
  portrait   "harin.png"      // 지금 — 조각 노드가 없는 리그(캐릭터)의 그 한 장
  skin       "꽃"             // 새로 — 조각 노드가 있는 리그에서 입는 스킨의 이름
```

- 처음 안("오브젝트마다 노드 → 그림 경로")을 버리고 **스킨**으로 간다: 조각(슬롯)마다 붙일 그림(어태치먼트)의 묶음에 이름을 붙이고, 오브젝트는 이름을 고른다.
  이모지 리그 하나에 "땀"·"꽃"·"느낌표"가 각각 스킨이다 — 이모지 정의의 "그림 부분"이 자연히 툴 안에 선다. 수년 검증된 모양을 새로 짓지 않는다.
- 그림이 없는 조각은 안 그린다(조각 하나짜리 이모지가 빈 조각 셋을 달고 다니지 않게). 그림을 줬는데 파일이 없으면 자리표시로 그린다.
- `portrait`는 그대로 둔다(캐릭터의 그 한 장).
- 조각의 크기: 그 노드의 rect(덤프) 그대로 그리거나 그림의 종횡비로 맞춘다 — 이모지는 그림마다 크기가 달라 **그림의 픽셀 크기를 기준 해상도 px로** 놓는 것이 맞아 보인다(런타임이 SetNativeSize를 하는지에 달렸다 — §5).

### 3.2 붙이기 — 되살리되 좁게

```
SceneObject
  attachTo   "s1"                 // 부모 오브젝트
  attachNode "CharSlot_Scale"     // 그 리그의 노드(런타임 결정: 슬롯 계층의 끝 — 초상 계층은 안 따라간다)
```

- `ScenePreview.Build`가 부모를 먼저 세우고 `AddRigTo(…, attachParentKey: "s1/CharSlot_Scale")`. 그리는 층은 부모의 것(런타임 결정: 앞 인물에 가려져도 된다).
- 예전 판(S6·S7)과 다른 점: 자유로운 계층이 아니라 **한 단계만**(붙은 것에 또 붙이지 않는다), 드래그로 부모 바꾸기·월드 위치 보존은 되살리지 않는다. 필요해지면 그때.
- 부모를 지우면 붙은 것도 같은 되돌리기 칸에서 사라진다. 이름을 바꾸면 따라온다(클립의 배역 묶임이 따라오는 것과 같은 식).
- 붙은 오브젝트의 `stage`·`layer`·`place`는 뜻이 없다(부모의 것) — 채널 박스에서 숨긴다. 오프셋·회전·배율은 붙는 자리에 대한 값으로 남는다
  (리그에 배치 축이 없으면 루트에 들어가는 지금 규칙 그대로).

### 3.3 불투명도 — 미리보기

- 포즈(`RectNodeTree`)에는 불투명도가 없다. `MotionPreview`가 트리와 함께 **노드 키 → 불투명도** 표를 낸다(클립의 `ClipStage.OpacityOf`가 이미 오브젝트 단위로 하는 일을 노드 단위로).
- 그릴 때는 그림 노드에서 루트까지의 불투명도를 곱한다(CanvasGroup이 그렇게 겹친다).
- 채널 박스·그래프: 종류 `alpha`, 성분 하나, 값 0~1. 매니퓰레이터는 없다(값 칸과 그래프로).
- 굽기: 알파 채널도 굽는다(곱).

### 3.4 클립과의 관계

- 손댈 것이 없다. 이모지 오브젝트를 배역에 묶으면 타임라인·클립 안에서 고치기·블록 끄기·굽기가 그대로 돈다.
- 보이기 상태 블록(오브젝트 전체의 페이드)과 알파 채널(노드의 불투명도)은 곱해진다 — 서로 다른 축이다.

## 4. 단계

| 단계 | 내용 | 기다리는 것 | 끝났다는 증거 |
|---|---|---|---|
| **P0** 결정 | 불투명도 = 모션 채널 — **했다**. 로케이터·반전(§5) | 소유자 · 런타임 확인 | |
| **P1** 여러 그림 — 완료(스킨으로) | 그림 노드 판정(덤프 표시, 없으면 이름 규칙) · `SceneObject.parts` · 편집기 명령(조각 그림 지정, 한 칸) · 저작본 왕복 · 뷰포트가 조각마다 그린다 · 씬 탭의 조각 그림 칸 | 없다(시험용 이모지 리그는 테스트 픽스처로) | 조각 넷인 리그에 그림 둘을 주면 둘만 그려진다. 캐릭터는 전과 같다 |
| **P2** 붙이기 — 완료 | `attachTo`·`attachNode` · `ScenePreview`가 부모 노드 밑에 세움 · 지우기·이름 바꾸기 따라가기 · 하이어아키에 붙은 것 표시 · 채널 박스 정리 | 없다 | 캐릭터를 옮기면 붙은 리그가 같은 양만큼 간다. 초상 계층의 모션에는 안 따라간다 |
| **P3** 비-character 만들기 — 완료 | 하이어아키 메뉴에 "붙는 리그 만들기 ▸ (덤프의 rigKind)" — 고른 캐릭터에 붙여 만든다 · 모션 추가가 그 rigKind로 | 없다(덤프에 이모지 리그가 없으면 메뉴가 빈다) | 이모지 리그를 만들고 그 노드에 키를 놓아 모션이 선다. 클립에 배역으로 묶여 캐릭터와 같이 돈다 |
| **P4** 불투명도 채널 — 완료(코어 선반영) | 코어 재반입 → `motions/3` 쓰기·읽기 · 그래프·도프 시트·채널 박스의 종류 · 미리보기의 불투명도 표 · 검증(`hasCanvasGroup` 노드만) · 굽기 · 골든 | **런타임 §2.1·§2.3** | 조각 하나가 0.4초 동안 흐려지는 모션을 만들어 내보낸 바이트가 런타임 로더에 읽힌다 |
| **P5** 문서 | README · USER-GUIDE · HANDOFF · `PLAN.md` §8 | | |

P1~P3은 코어를 기다리지 않는다 — 이것만으로 "튀어나옴·punch·떠다님"까지 만들고 본다. P4가 들어오면 "흐려지며 사라짐"이 붙는다.

크기: P1이 뷰포트 그리기, P2가 `ScenePreview`와 편집기, P4가 종류 하나를 여러 화면에 꿰는 일이다. 어느 것도 모션 모델·클립 모델을 바꾸지 않는다.

## 5. 열린 질문

1. **로케이터.** → **기준점 표로 푼다(§11, 2026-11-10).** 아래는 그때의 질문. 캐릭터 리그에 자리 노드를 새로 둘지, 코어의 기준점 표(focus — `faceAura`·`face`·`handLeft`…, `place`가 쓰는 캐릭터별 값)로 자리를 줄지.
   툴은 어느 쪽이든 된다 — 앞이면 `attachNode`가 그 노드, 뒤면 `attachNode = CharSlot_Scale` + 붙는 오브젝트의 오프셋을 기준점에서 푼다(툴의 `place`가 이미 하는 계산).
   뒤쪽이 캐릭터 리그를 안 건드리고 캐릭터마다 다른 머리 자리를 기존 데이터로 푼다.
2. **좌우 반전.** 소유자: 뒤집히고, 방향이 맞아야 한다(날아가는 하트). 런타임 결정은 "초상 계층은 무시" — 반전이 초상 계층의 일이면 지금 붙는 자리로는 안 따라온다.
   반전이 어느 노드의 일인지, 그림의 좌·우 판이 "어느 쪽에 뜨는가"인지 "어디를 향하는가"인지 확인이 필요하다. 툴은 반전을 붙는 리그 루트의 배율 x = −1로 미리본다.
3. **조각 그림의 크기.** 노드 rect에 맞추나, 그림의 픽셀 크기 그대로 놓나.
4. **캐릭터의 fade 표적에 알파 모션.** §2.1의 소유권 — 이모지만 쓸 거라면 미뤄도 된다.

## 6. 하지 않는 것

- 이모지 **정의**(키 → 그림·등장/퇴장 모션·머무는 시간·자리·프레임 묶음)를 툴에서 만들기 — 런타임의 데이터다. 툴은 모션을 만들고, 정의가 그 이름을 가리킨다.
  정의까지 툴에서 고르고 미리보는 것은 정의의 모양이 선 뒤에 따로 정한다.
- 그림 넘기기(프레임 묶음)의 미리보기 — 조각의 그림은 한 장으로 본다.
- 붙은 것에 또 붙이기, 드래그로 부모 바꾸기.
- 스프라이트 교체 채널(모션이 그림을 바꾸는 것) — 계단 키가 필요하고 규약이 계단 탄젠트를 거부한다. 필요해지면 별 규약.
- 코어 사본 수정.

## 7. Spine에서 배우는 것 (소유자, 2026-11-10: "수년에 걸쳐 검증된 것은 새로 만들 필요가 없다")

이 툴이 Spine보다 나은 점은 분명하다 — AI 친화적(JSON·결정적 검증), 리그와 모션이 런타임과 같은 함수로 보장됨, shot·depth, 마야식 커브. 그 위에 검증된 것을 얹는다.

| Spine의 것 | 여기서의 자리 | 언제 |
|---|---|---|
| 슬롯 · 어태치먼트 · 스킨 | 조각 노드 · 그림 · `SkinAsset` | P1 — 했다 |
| 포인트 어태치먼트(이름 붙은 점, 스킨마다 값) | 붙는 자리 = 이름 붙은 점(코어의 기준점 표 focus) — §5의 1 | P2 |
| 루트를 뒤집으면 붙은 것도 뒤집힌다 | 반전은 붙는 지점보다 위에서 — 붙은 리그 루트의 배율 x = −1로 미리본다 | P2 |
| 반복 재생 · 대기열 | 모션은 한 번만 돈다 — 머무는 이모지의 punch 반복 | 다음(규약 필요) |
| 이벤트 키 | 모션에 이벤트가 없다 — "이 프레임에 이모지·소리" | 다음(규약 필요) |
| 트랙별 겹치기(섞기·더하기) | 한 노드의 두 모션은 런타임에서 미정 — 지금은 굽기 | 뒤 |
| 계단 키 | 규약이 거부 — 그림 교체·그리는 순서 | 뒤 |
| 어니언 스킨 · 미리보기 내보내기(GIF) | 없다 | 뒤 |
| 메시 · 가중치 · IK · 경로 제약 | **가져오지 않는다** — 초상 한 장을 움직이는 구조에 쓸 자리가 없다 | — |

Spine에 없는 이 툴의 방향: **창 없이 도는 명령줄 도구**(검증·내보내기·그 시각의 포즈·굽기) — AI가 모션을 쓰고 검증하고 결과를 읽는 고리. P1~P3 뒤의 추천 순서는
반복 재생 → 이벤트 키 → 명령줄 도구(앞의 둘은 런타임 규약이 같이 바뀐다).

## 8. 이모지 정의 — 툴에서 만든다 (소유자, 2026-11-10)

§6은 "정의는 런타임의 데이터 — 툴은 모션만"이라 했다. **바뀌었다**: 스킨(그림)이 툴 안에 섰고 불투명도·이벤트·반복까지 모션으로 들어왔으니,
그것들을 이모지 하나로 묶는 정의도 여기서 만들고 수명 전체를 미리본다. 정의의 모양이 곧 런타임에 보내는 규약 초안이다.

```
EmojiAsset                       // 저작본 "emojis": [...] · 산출물 emojis.json (emojis/1-draft)
  name         "sweat"           // 대본이 부르는 키 — 빈칸 없는 글(한글도 된다)
  rig          "emoji"
  skin         "땀"              // 산출물에는 풀어서: "parts": { "Emoji_Part1": "art/sweat.png" }
  enter        "pop"             // 한 번
  hold         "bob"             // 머무는 동안 처음부터 되풀이
  exit         "fade"            // 한 번
  holdSeconds  1.0               // 없으면 끌 때까지 머문다 → 산출물 "stay": true
  anchorNode   "Emoji_Anchor"    // 오프셋이 들어가는 노드
  offset       [120, 300]        // 붙는 자리에서의 px
  locator      "faceAura"        // 기준점 이름 — 붙은 캐릭터의 그 점에서부터 offset을 잰다(§11). 없으면 붙는 노드에서부터
```

**수명의 뜻(규약 초안).**
1. 뜬다 — 리그가 캐릭터의 붙는 자리에 서고, `anchorNode`에 `offset`이 들어가고, `parts`의 그림이 붙는다.
2. `enter`를 한 번 돈다(끝 규칙 그대로 — commit이면 그 자세가 남는다).
3. `hold`를 **등장이 끝난 자세에서 처음부터** 되풀이한다(바퀴가 쌓이지 않는다 — Spine의 loop). `holdSeconds`가 다하면 그 순간의 자세에서 멈춘다.
4. `exit`를 한 번 돌고 사라진다.
5. `holdSeconds`가 없으면(`stay`) 4는 `emoji_off`가 올 때 시작한다 — 이것은 **상태**다(되감기에서 살아 있어야 한다). 있으면 **이벤트**다(끝 상태가 없다).

**모션의 재생 기준.** 툴은 각 모션의 재생 기준(상대값/절대값)으로 미리본다. 이모지 리그는 매번 처음 자세에서 뜨므로 대개 둘이 같다 —
런타임이 정의에 재생 기준을 따로 받을지는 열려 있다.

**하지 않는 것(지금).** 그림 넘기기(프레임 묶음) ·
좌·우 판 · 감정 묶음(표정 + 이모지 + 컷인 테마) · 모션의 이벤트 키(`emoji` · 값 = 키)가 울릴 때 클립 미리보기에서 그 이모지를 띄우는 것(다음 후보).

## 9. 리그도 툴에서 — 붙는 리그는 툴이 원본 (소유자, 2026-11-10)

"Spine도 툴에서 먼저 정의하고 유니티가 쓴다." 모션·스킨·이모지 정의는 이미 그 방향이었고, 리그만 반대(유니티 덤프 → 툴)였다.
**캐릭터 리그는 그대로 덤프가 원본**(프리팹·깊이·자리·카메라가 그 구조에 맞물려 있다)이고, **새로 만드는 붙는 리그(이모지 등)는 툴이 정의해 내보낸다.**
`HANDOFF.md` §2의 "리그는 만들지 않는다"에 예외가 생긴다 — 갈리는 선은 "유니티에 이미 있는 것인가, 새로 만드는 것인가"다.

```
RigAsset                          // 저작본 "rigs": [...]
  kind   "emoji"
  nodes[]                         // 부모가 자식보다 먼저. 루트(__root)는 적지 않는다 — 내보낼 때 붙는다
    id · parent · x · y · width · height · image(그림을 그리는가) · alpha(불투명도를 받는가)
```

- 노드는 단순하다: 부모 가운데에 앵커·피벗을 둔 사각형. 코어의 리그 스키마(`RigSchemaRigDto`)로 바꿔 **덤프의 리그와 한 벌로** 쓴다(`RigAssets.Compose`) —
  그 뒤는 전부 같은 길이다(트리 세우기·검증·조각·불투명도 노드).
- 같은 rigKind가 덤프에도 있으면 **문서의 것이 이긴다**. 런타임이 나중에 같은 리그를 덤프해도 툴의 정의가 원본으로 남는다.
- 산출물은 **덤프와 같은 모양**(`rig-schemas.json`의 그 형식) — 런타임은 캐릭터 덤프를 읽는 그 로더로 읽어 세운다. 그림 노드는 `hasImage`(§2.2, 코어 선반영), 불투명도는 `hasCanvasGroup`.
- 본: `RigTemplates.Emoji` — `Emoji_Anchor › Emoji_Body › Emoji_Part1…4`(160px). 조각의 수·크기는 `SetRigParts`로. 노드를 하나씩 짓고 옮기는 것은 리그 편집기(§12).
- 화면: "붙는 리그 만들기 ▸ emoji"와 "이모지 추가"가 **리그가 없으면 같은 되돌리기 칸에서 정의한다** — 덤프를 기다릴 것이 없다.

## 10. 이벤트 키로 이모지 띄우기 (소유자, 2026-11-10: "진행")

"표정 변화와 함께 머리 옆에 뜬다"를 툴에서 본다. 캐릭터 모션의 이벤트 키가 울리면, **그 캐릭터에 붙은 이모지 리그**가 이모지 정의(§8)의 수명을 돈다.

| 이벤트 | 뜻 (런타임에 요청하는 규약 — 초안) |
|---|---|
| `emoji` · 값 = 이모지 키 | 울린 캐릭터에 그 이모지를 띄운다. 울린 시각이 수명의 0초 — 등장 → 머묾 → 퇴장. 수명은 모션보다 길어도 된다(모션이 끝나도 이모지는 제 수명을 마친다) |
| `emoji_off` (값 안 봄) | 그 캐릭터의 지금 이모지를 끈다 = **그 순간 퇴장이 시작한다**. 등장 중이면 등장을 마치고 퇴장한다. 머무는 이모지(머무는 시간 없음)는 이것이 올 때까지 떠 있고, 시간이 정해진 이모지도 일찍 끌 수 있다 |

- **한 캐릭터에 이모지는 하나.** 새 `emoji`가 울리면 앞의 것을 퇴장 없이 갈아 치운다. 모르는 키도 "갈아 치움"이다(아무것도 안 뜬다).
- 상태가 아니다(§2.5) — 건너뛰기·되감기에서 다시 뜨지 않는다. 다만 **미리보기는 스크럽한 자리에서 "그때 떠 있었을 것"을 보인다**(처음부터 그 시각까지 울린 것을 다시 센다).
- 연기하는 오브젝트: 그 캐릭터에 붙어 있는, 정의와 같은 리그의 첫 오브젝트. **없으면 미리볼 데가 없다**(런타임은 그때 리그를 세운다 — 툴에서는 캐릭터 우클릭 → 붙는 리그 만들기).
  그 오브젝트는 **이벤트가 부리는 동안 떠 있을 때만 보인다**(뜨기 전·사라진 뒤에는 없다). 떠 있는 동안에는 제가 입은 스킨 대신 정의의 스킨을 입고, 자리는 정의의 오프셋이다.
- 클립: 블록이 놓인 시각부터 세고, 반복하는 블록은 바퀴마다 다시 띄운다. 끈 블록·끈 배역은 안 띄운다. 이모지 오브젝트를 배역에 묶어 직접 모션을 놓는 것(§3.4)과는 따로다 — 둘을 섞으면 이벤트가 나중에 얹힌다.
- 모션 하나만 볼 때는 시계가 모션 길이라 **모션보다 긴 수명은 끝까지 안 보인다** — 클립에 놓으면 다 보인다.
- 검증: `emoji` 이벤트의 값이 문서의 이모지 키가 아니면 알린다(막지 않는다 — 런타임의 표가 따로일 수 있다. 문서가 이모지를 하나도 정의하지 않았으면 말하지 않는다).
- 코드: `Preview/EmojiEvents.cs`(`Resolve` — 울린 이벤트 → 도는 이모지, `Pose`, `Targets`) · `EmojiPreview.PlayPhases`(실제로 도는 길이) · 뷰포트 `EmojiPlaysAt`·`IsDormantEmoji`·`SetSkinImage`.
- 남은 것: `mt pose`가 도는 이모지를 내기 · 구울 때(`ClipBake`) 이벤트로 뜬 이모지는 굽지 않는다 · 이모지끼리 겹쳐 띄우기(한 캐릭터에 둘)는 규약 밖.

## 11. 붙는 자리(로케이터) — 기준점 표로 푼다 (소유자, 2026-11-10: "예")

§5의 1에서 **뒤쪽**을 골랐다: 캐릭터 리그에 자리 노드를 새로 두지 않고, 코어의 기준점 표(focus — `place`가 쓰는 그 표)로 푼다.

- `locator`가 기준점 이름(`faceAura`·`face`·`bust`·`body`·`feet`·`handLeft`·`handRight`, 대본 표기 `face_aura`도 받는다)이면,
  **붙은 캐릭터의 그 점**이 이모지 자리 노드(`anchorNode`)의 원점이 되고 `offset`은 거기서부터다. 없으면 전과 같이 붙는 노드에서부터.
- 점: `FocusOffsetMath.Resolve`(표의 합)를 초상 계층의 측정 노드(`CharacterPortrait_VisualOffset`)에서 잰 것 — `place`와 같은 점이다.
  자리 노드를 그리로 보내는 값도 `place`의 풀이(`SettledFocusMath.SolveFocusPlacement`) 그대로. 새 수학은 없다.
- **뜨는 순간 한 번, 가만히 선 무대에서** 푼다(`place`가 커맨드 순간 한 번 풀리는 것과 같다) — 떠 있는 동안 캐릭터의 초상 계층 모션을 따라가지 않는다(런타임 결정 그대로).
  슬롯 계층(자리·깊이·오프셋·배율)은 붙어 있으니 따라간다: 캐릭터가 어디에 서든 그 점이다(테스트).
- **런타임에 요청하는 규약(초안):** `emojis.json`의 `locator` + `offset` = "그 캐릭터의 기준점 + 자리 노드 좌표의 오프셋". 기준점은 런타임의 표(배역별 값 포함)로 푼다.
- **배역별 값 — 배역 키(소유자, 2026-11-10: "나중에 해야 한다면 지금").** `SceneObject.Character`(런타임 `cast`의 characterKey). 적으면 `place`·깊이의 focus 보존·로케이터가
  표의 그 배역 값(`base + 배역 공통 + 배역의 기준점별`)으로 풀린다 — 코어의 그 인자에 빈 글 대신 키를 넘길 뿐이다. 비우면 전과 같이 기본값만, 표에 없는 배역도 기본값.
  기존 문서는 안 바뀐다(키를 적은 오브젝트만 달라진다). 붙은 오브젝트는 부모의 배역을 따른다. "씬" 탭의 **배역** 칸, `MotionEditor.SetObjectCharacter`.
  깊이 컨트롤러를 모션에 굽는 값(`DepthTuningFile.FocusHeightOf`)은 그대로 기본값이다 — 모션은 rigKind의 것이라 어느 배역에도 같아야 한다.
  런타임의 표에 배역별 값은 아직 없다(2026-11-10) — 채워지면 `presets/focus.json`을 다시 덤프해 덤프 옆에 둔다. 표를 툴에서 고치는 것은 하지 않는다.
- 검증: 모르는 이름은 알린다(막지 않는다 — 런타임이 이름을 더 알 수 있다). 미리보기는 그때 오프셋만 쓴다.
- 코드: `EmojiPreview.LocatorPoint` · `Pose(…, origin)` · `EmojiEvents.Pose(…, originOf)` · 뷰포트 `EmojiOrigin`(이모지 정의 보기와 이벤트로 뜬 이모지 모두).
- 좌우 반전(§5의 2)은 그대로 열려 있다 — 반전된 캐릭터에서 `handLeft`가 어느 쪽인지는 코어의 facing 축이 폴드에 오를 때 정해진다.

## 12. 리그 편집기 — 노드를 하나씩 짓고 옮긴다 (소유자, 2026-11-10: "진행")

범위는 **툴이 정의한 리그만**(§9). 캐릭터 리그는 덤프가 원본이라 목록이 비고 칸이 잠긴다.

| 명령(각각 한 칸) | 뜻 |
|---|---|
| `AddRigNode(kind, id, parent, image)` | 부모의 식구들 맨 뒤에 선다(= 가장 위에 그려진다). 그림 노드는 본의 크기(160)와 불투명도를 갖고 선다 |
| `RemoveRigNode` | 밑의 노드도 함께. 그 노드를 쓰던 채널·스킨 칸은 남고 검증이 알린다(되살리면 다시 맞는다) |
| `RenameRigNode` | **따라온다**: 자식의 부모 · 그 리그의 모션 채널 · 스킨의 조각 칸 · 이모지의 자리 노드 · 그 리그에 붙은 오브젝트의 붙는 노드 |
| `UpdateRigNode` | 위치 · 크기 · 그림을 그리는가 · 불투명도를 받는가. 같은 값은 무기록 |
| `SetRigNodeParent` | 식구째 새 부모의 맨 뒤로. 제 밑으로는 못 옮긴다 |
| `MoveRigNode(±1)` | 형제 사이의 순서(= 그리는 순서) — 식구째 맞바꾼다 |

- 불변식: **부모가 자식보다 먼저 온다**(세울 수 있는 리그) — 모든 명령이 식구(밑의 노드 전부)를 한 덩어리로 옮겨 지킨다.
- 노드 이름: 영문자로 시작하는 영문·숫자·`_`. 조각 판정은 `image` 표시가 먼저다(이름 규칙 `_Part<숫자>`는 표시 없는 덤프용).
- 화면: "이모지" 탭 리그 칸 아래 — **다루는 리그**(비우면 고른 이모지·오브젝트의 리그) · **새 리그**(노드 `Body` 하나, 이름 `rig`·`rig_2`…) ·
  노드 목록(들여쓰기 = 계층, ▣ 그림 · α 불투명도) · 노드 / 그림 노드 / 삭제 / ▲▼ · 이름·부모·X·Y·너비·높이·두 체크.
  고치면 문서의 리그가 덤프와 다시 합쳐져 뷰포트가 바로 따라온다. 새 리그는 하이어아키의 "붙는 리그 만들기"에 뜬다.
- 하지 않은 것: 뷰포트에서 노드를 끌어 놓기(가만히 선 자세를 손으로) · 노드의 회전·배율·앵커·피벗(지금은 가운데 고정 — 필요해지면 `RigNodeAsset`에 더한다) ·
  리그 이름 바꾸기·복제 · 드래그로 부모 바꾸기.

## 13. 예시를 지으며 걸린 곳을 고친다 — 스킨의 덧붙임 · 반전 판 (소유자, 2026-11-10: "걸린 지점을 고칩시다")

이모지 22종을 실제 그림으로 세팅해 보니(`examples/emoji`) 네 군데가 걸렸다. 넷 다 **"그림의 일을 모션이 대신하고 있었다"**는 한 가지다 — Spine이 어태치먼트에 두는 것을 스킨에 둔다.

| 걸린 곳 | 전 | 고친 것 |
|---|---|---|
| 그림 넘기기 | 장마다 조각 하나 + 불투명도 키로 켜고 끄기, 전용 등장 모션 | **조각 하나에 장 여럿**(`SkinPartSetup.Frames`) + 장당 시간 + 되풀이/마지막에서 멈춤 — Spine의 sequence |
| 조각의 자리 | 리그의 조각이 전부 한가운데 → 꽃 셋의 자리를 등장 모션의 키로 | **놓임**(`X`·`Y`·`Scale`·`Rotation`) — 조각 노드 안에서. 노드의 값(모션)과 따로다 |
| 좌·우 판 | 그림만 다른 정의를 통째로 복제 | 이모지의 **반전 판 스킨**(`SkinFlipped`) — 정의는 하나 |
| 튀는 머묾 | 복원 모션이 중립값에서 끝나야 해서 막힘 | 규칙은 그대로(런타임의 것). 머묾은 '유지' 모션으로 — 이모지의 머묾이 바퀴마다 처음 자세에서 다시 돌린다. 칸의 풍선말에 적었다 |

**규약(초안 — 런타임에 요청).**
- 그림 넘기기: 뜬 뒤 `floor(t / frameSeconds)`번째 장. `loop`면 장 수로 나눈 나머지, 아니면 마지막 장에서 멈춘다. **시각은 이모지가 뜬 순간부터**(모션의 바퀴와 무관하다).
  상태가 아니다 — 그림만 바뀐다. 이모지가 아닌 오브젝트가 입은 스킨이면 시계의 시각이다(툴의 미리보기).
- 놓임: 조각 노드의 rect 안에 그림을 종횡비로 맞춘 뒤, 노드의 px로 `x`·`y`만큼 옮기고 가운데 기준으로 `scale`배·`rotation`도(반시계 +). 노드의 위치·배율·회전(모션)은 그 바깥에서 곱해진다.
- 반전 판: 붙은 캐릭터가 좌우 반전이면(조각 사각형의 손잡이 방향으로 판정) 반전 판 스킨을 입고 **그림을 뒤집지 않고** 그린다. 자리와 움직임은 계층이 뒤집는다.
  반전 판이 없으면 같은 그림이 계층을 따라 뒤집혀 보인다(§5의 2 — 소유자: "뒤집힌다").
- 산출물 `emojis.json`: `parts`의 값이 한 장·제자리면 글 하나(전과 같다), 아니면 `{ "image", "frames", "frameSeconds", "loop", "x", "y", "scale", "rotation" }`(기본값인 묶음은 안 적는다). 반전 판은 `partsFlipped`.

**코드.** `SkinAsset.Setups`·`ImagesOf`·`ImageAt`·`AllImages` · `MotionEditor.SetSkinPartImages`(장들을 한 칸에)·`SetSkinPartSetup` · `EmojiAsset.SkinFlipped` ·
뷰포트는 그림을 **문서 기준 경로**로 싣고(`SetImage`) 그릴 때 고른다(`WornBy` — 입은 스킨 · 정의의 스킨 · 반전 판 · 지금의 장). 전의 `SetPartImage`·`SetSkinImage`·`LoadEmojiImages`는 없앴다.
화면: "씬" 탭 스킨 칸의 그림 칸에 `a.png | b.png`로 여러 장, 그 아래 장당 초·되풀이·놓임(X·Y·크기·회전). "이모지" 탭에 반전 판.

**이모지 탭에서 스킨을 바로(2026-11-10).** 스킨 칸은 고른 오브젝트가 **입은** 스킨만 고쳤다 — 이모지의 스킨을 고치려면 오브젝트에 입혀야 했다.
"이모지" 탭이 그 이모지의 스킨(과 반전 판)의 조각 줄을 그 자리에 세운다("씬" 탭과 같은 줄 — `SkinPartRow`). **새 스킨** / **새 반전 판**은 이모지의 이름으로 스킨을 만들어
그 칸에 꽂는다(한 칸 — `Batch`). 화면을 뽑아 보니 이모지 목록이 22줄로 화면을 다 차지해 칸들이 밀려나 있었다 — 목록에 높이 상한을 뒀다.

**남은 불편.**
인스펙터 탭이 다섯이라 한 줄에 안 들어간다 · 끊기는 키(step)가 여전히 없다(그림 넘기기에는 이제 필요 없다).

## 14. 조각을 끌어서 놓는다 (소유자, 2026-11-10: "조각이 여럿인 이모지가 꽤 많다")

놓임(§13)을 숫자 칸 대신 뷰포트에서 잡는다. **이모지 정의를 보는 중**("이모지" 탭에서 정의를 골랐을 때)에만 — 그때 뷰포트의 끌기는 모션의 키가 아니라 스킨의 값이다.
(모션·클립을 볼 때의 끌기는 전과 같이 기즈모로 포즈를 잡는다 — Auto Key면 놓는 순간 키.)

| 손 | 바뀌는 것 |
|---|---|
| 조각 끌기 | 놓임의 자리 X·Y — 노드의 px(1px로 반올림). 부모들의 배율(캐릭터의 깊이 배율 등)을 거꾸로 풀어 "끈 만큼" 간다 |
| Shift+끌기 | 크기 — 가운데에서의 거리 비(0.01로 반올림, 0.05 아래로는 안 간다) |
| Ctrl+끌기 | 회전 — 가운데 둘레(1도로 반올림, 반시계 +) |

- 위에 그려진 조각이 먼저 집힌다. 집은 조각은 윤곽으로 보인다(빈 자리를 누르면 풀린다).
- **끈 하나 = 되돌리기 한 칸.** 끄는 동안에는 그림만 따라오고 문서는 안 바뀐다. 제자리에서 놓으면 기록이 없다.
- 반전 판을 입고 있을 때(캐릭터가 좌우 반전) 끌면 반전 판 스킨의 놓임이 바뀐다 — 보이는 그 스킨을 고친다.
- 놓임 칸("이모지" 탭)이 따라온다. 단축키 표(F1)에 적었다.
- 코드: `ViewportView.TryStartPartPlacement`·`DragPartPlacement`·`EndPartPlacement`, 끄는 중의 값은 `PlacementOf`가 낸다.
- 하지 않은 것: 축 고정(Shift = 한 축)·스냅·여러 조각 한꺼번에·기즈모 손잡이(지금은 조각 그림 자체를 집는다).

## 15. 이모지를 보면서 구간의 모션을 고친다 (소유자, 2026-11-10)

"등장·머묾·퇴장의 모션을 고른 그대로 그래프에 띄우고, 멈춘 채 고쳐서 그 이모지를 완성한다." 클립 안에서 고치기(`PLAN-clip.md` K4b)와 **같은 꼴**이다 —
이모지는 고른 채로 남고, 그래프·도프 시트만 그 구간의 모션에 묶인다.

- "이모지" 탭의 **고치기: 등장 / 머묾 / 퇴장**(하나만, 다시 누르면 푼다). 고르면 시계가 그 구간의 처음으로 가고 그래프에 그 모션이 뜬다.
- 뷰포트의 끌기·채널 박스·S·Auto Key·불투명도 칸이 **그 모션**에 키를 놓는다. 지금 시각이 그 구간 안일 때만(밖에서는 그 모션이 안 보인다).
- 시각: 그래프는 모션 기준(0부터), 시계와는 구간의 시작만큼 어긋난다. **머묾은 지금 바퀴의 처음**이 0초다 — 바퀴가 넘어가면 그래프의 시각이 다시 돈다.
  구간의 경계는 앞 구간의 것(등장의 끝 = 등장의 마지막 키).
- 시작값(키 값을 푸는 기준): 그 구간이 얹히기 **전**의 자세 — 등장은 자리만 잡힌 처음 자세, 머묾은 등장이 끝난 자세(바퀴마다 같다), 퇴장은 머묾이 멈춘 자세.
  미리보기와 같은 함수(`EmojiPreview.PoseBefore`)라 놓은 키가 보이는 자리에 그대로 선다.
- 구간을 안 골랐으면 뷰포트의 끌기는 조각의 놓임이다(§14) — 두 손이 섞이지 않는다.
- **타임 슬라이더의 키 틱**: 슬라이더는 "묶인 모션"의 키만 그렸다 — 이모지·클립을 볼 때는 묶인 모션이 없어 비어 있었다(소유자가 짚었다).
  고치는 모션의 키를 **시계의 자리**에 그린다(`ViewportView.ContextKeyTimes` — 머묾·반복하는 블록은 바퀴마다). 보기만 한다: 범위 선택·키 옮기기는 그래프·도프 시트에서.
  클립 안에서 블록을 고칠 때도 같다.
  **구간을 안 골랐을 때**는 세 구간의 키를 다 그린다 — 등장 초록 · 머묾 노랑 · 퇴장 파랑(`EmojiKeyTimes`). 구간을 고르면 그 구간만 빨강.
- **키 없는 채널을 흐리게**(소유자: "scale만 있는 모션에 다른 값도 조금씩 같이 맞추고 싶다"): 그래프 목록 아래 **키 없음** 묶음에 그 모션이 아직 안 건드리는
  노드 × 종류(위치·배율·회전, 불투명도는 받을 수 있는 노드만)가 선다. 이름을 누르면 그 노드가 골라지고(손잡이·채널 박스가 본다), **＋**는 지금 값을 지금 시각의 키로 놓는다(채널이 생긴다).
  작은 리그(노드 16개 이하 — 이모지 등)에서만: 캐릭터 리그는 노드가 많아 목록이 묻히고, 그쪽은 컨트롤러 표가 같은 일을 한다. 이모지 밖에서 그 리그의 모션을 고를 때도 같다.

**함께 쓰는 모션.** 같은 `emoji_pop`을 여러 이모지가 쓴다 — 여기서 고치면 다 바뀐다. 그것이 뜻일 때도(전체의 '톡'을 다듬는다), 아닐 때도(이 이모지만 다르게) 있다.
- 고치는 구간 아래에 **누가 함께 쓰는지** 적힌다(이모지 이름들 · 클립 몇 곳).
- **이 이모지만의 모션으로**: 그 모션을 복제해(`이름_2`…) 이 이모지가 쓰게 한다 — 한 칸. 다른 이모지·클립은 원래 것을 그대로 쓴다(`MakeEmojiPhaseUnique` — 클립 블록의 "따로 떼기"와 같다).
- 하지 않은 것(더 고민할 것): 이모지마다의 **덮어쓰기**(원본을 따르되 몇 채널만 다르게) · 빠르기·세기 같은 **인자**(같은 모션을 0.8배 빠르게, 1.2배 크게).
  복제는 단순하지만 갈라진 뒤에는 원본을 고쳐도 안 따라온다 — 조금만 다른 판이 많아지면 인자가 낫다.

코드: `EmojiPhase` · `EmojiPreview.PhaseWindow`·`PoseBefore`·`MotionNameOf`·`UsesOf` · 뷰포트 `EmojiPhaseContext`·`EmojiPhaseTimeOffset`(EditMotion·EditTime·StartStateOf가 본다) ·
`MainWindow.SyncEmojiContext`(`SyncBlockContext`의 짝).
