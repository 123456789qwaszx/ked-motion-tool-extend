## 6. 알려진 불편과 남은 것

컷을 쓰면서 드러났지만 아직 안 고친 것:

- 그림 키가 타임 슬라이더에 틱으로 안 보인다("모션" 탭의 줄로만). 그림 키의 그림을 줄에서 못 바꾼다(지우고 다시 놓는다).
- 그림을 그리는 오브젝트는 원래 그림이 하나 있어야 한다(그림 키만 있고 원래 그림이 없으면 안 그려진다).
- 카메라는 하이어아키에 `Camera_Pan` · `Camera_Zoom` 두 점으로 보인다(골라서 채널 박스로 키를 놓는다) — 이름이 낯설다. "카메라" 한 항목으로 묶을 만하다.
- README 맨 아래의 "진행" 표와 `HANDOFF.md` · `MAINTENANCE.md`의 본문은 옛 내용(캐릭터 모션 · 덤프) 그대로다.
- "화면 밖에서 들어온다"의 거리가 깊이에 따른 크기를 모른다.
- 컷 파일을 툴로 다시 들이는 길 · CLI의 컷 내보내기가 없다.
- 저작본 안의 키 시각은 아직 초다(화면과 컷 파일은 프레임).

## 7. 소유자가 정해야 하는 것

- **(screenTransition 세션의 질문 여섯 — 그 저장소 계획서 §10.4)** 여기서 낸 의견은 대화에 있다. 요지:
  1. 컷 파일과의 관계 — 뼈대만 닮게, 코드는 그쪽의 것(동의). 키를 적는 방식(프레임 · `f v i o` · 그림은 계단 키)은 똑같이 지킨다.
  2. "틀"까지 간다 — 단, 전환 하나에 틀 하나.
  3. 글 — 자리와 움직임만, 내용은 매개변수(맨 뒤에). 글의 실제 크기를 툴이 모른다는 한계.
  4. 가림 — 사각형 + 그림 가림부터. 사각형 가림은 처음에는 기울지 않은 것만.
  5. 대상 런타임 — 유니티 UGUI 하나를 기준으로.
  6. 옛 산출물과 이름 — 계획 그대로. 이름 바꾸기는 T2와 같이.
- 1번이 그렇게 정해지면 **이 저장소의 `PLAN-standalone.md`("세 갈래로 가른다" 절)의 한 문장을 고친다**: "화면 전환 쪽이 이 저장소의 `Ked.Presentation.Core/Cut/`을 가져다 쓴다" → 가져다 쓰지 않는다(뼈대와 키를 적는 방식만 같다).

## 8. 일하는 방식 (이 세션에서 굳은 것)

- 소유자는 "진행."으로 다음 단계를 연다. 단계가 끝나면 **된 것 · 정한 것 · 아직 불편한 것 · 다음**을 짧게 보고한다.
- 권고가 틀렸으면 바로 철회하고 계획서에 그렇게 적는다(씬을 없애자던 것 · 카메라를 없애자던 것 · 텍스트를 신경 쓴 것이 그랬다).
- 소유자가 이미 답이 있는 것(깊이는 `depthLevel` 수다 · 컷과 텍스트는 상관없다 · 소리는 지금 안 다룬다)을 다시 묻지 않는다.
- 새로 짓기보다 **있는 것을 올린다**(컷은 세트의 그릇 위에 섰고, 카메라와 깊이는 "값만 담는 점"으로 타임라인에 실었다 — 그래서 그래프·도프 시트·되돌리기가 그대로 돈다).
- 그 밖의 관습은 `CLAUDE.md`.
