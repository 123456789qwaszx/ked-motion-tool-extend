# 세트 — 오브젝트를 놓고, 키를 넣고, 묶어서 가져다 쓴다

상태: **설계 합의(2026-11-10). 최종 형태는 조립(§7) — S1부터 구현 중.** 이 문서는 이모지에서 시작한 작업(`PLAN-parts.md`)을 **범용 구조**로 다시 세우는 계획이다.

## 0. 왜 다시 세우나

이모지 22종을 세팅하고 나서 소유자가 짚었다: *"이모지 전용으로 한 것은 너무 부분적이다. extend는 화면 사이 이동 연출·배경 이동 같은 것을 만들려고 하는 것이다."*
참고 영상 셋(날짜 소개 · 캐릭터 소개 · 화면 이동)을 보니 이모지용 가정이 다 깨진다:

| 이모지용 가정 | 실제 연출 |
|---|---|
| 같은 조각 넷을 미리 깔아 둔 고정 리그 | 건물·해·차·패널이 전부 다른 노드다(8개 이상). 요소마다 제 구조 |
| 모션을 여럿이 나눠 쓴다 | 화면 이동의 모션은 화면 이동만의 것 |
| 캐릭터에 붙는다 | 화면 전체에 선다 |
| 노드는 그림만 그린다 | 색 사각형 · 글자 |
| 내용이 고정이다 | 날짜·이름·어느 캐릭터인지가 부를 때마다 다르다 |

데이터 구조는 크게 틀리지 않았다(툴이 정의한 리그 + 그 리그의 모션 + 스킨). **틀린 것은 작업 순서와 이름이다** — 구조를 숫자 칸으로 먼저 정의하고, 모션을 따로 만들고, 그다음 오브젝트를 세운다. 전부 "이모지" 탭 안에서.

## 1. 모델 — 마야의 작업 방식 + 스파인의 쓰는 방식

> 오브젝트를 화면에 놓고, 그 오브젝트에 키를 넣고, 그 덩어리를 통째로 가져다 쓴다.

- **마야에서**: 오브젝트를 화면에 직접 놓고 계층으로 묶고, 그 오브젝트에 바로 키를 넣는다.
- **스파인에서**: 그렇게 만든 것이 "뼈대 + 이름 붙은 애니메이션들" 한 덩어리가 되고, 쓰는 쪽은 그 덩어리를 불러 "이 애니메이션을 재생"만 한다. 배치(Setup)와 애니메이션(Animate)이 다른 모드다.

### 낱말

| 낱말 | 뜻 | 지금의 무엇인가 |
|---|---|---|
| **세트** | 오브젝트들의 계층 + 그 그림 + 이름 붙은 애니메이션들. 화면 이동 하나, 날짜 소개 하나, 이모지 무리 하나가 각각 세트다 | 툴이 정의한 리그(`RigAsset`) + 그 rigKind의 모션들 + 스킨들 |
| **오브젝트(노드)** | 세트 안의 하나 — 그림 · 색 사각형 · 글자 · 초상 자리 · 묶는 것 | `RigNodeAsset`(지금은 그림/묶음뿐) |
| **애니메이션** | 세트의 오브젝트들에 놓인 키의 묶음, 이름으로 부른다 | 모션(`MotionAsset`) |
| **스킨** | 같은 세트에 다른 그림 — 이모지 22종은 "이모지 세트"의 스킨 22개다 | `SkinAsset`(+ 놓임 · 그림 넘기기) |
| **연출** | "이 세트를, 이 스킨으로, 등장·머묾·퇴장은 이 애니메이션으로, 여기에 세운다"에 붙인 이름. 대본이 이 이름으로 부른다 | `EmojiAsset`(캐릭터에 붙는 것만) |
| **클립** | 세트들을 장면에 놓고 언제 어떤 애니메이션을 틀지 | `ClipAsset`(그대로) |

캐릭터는 "유니티가 구조를 정해 준 세트"다 — 같은 자리에 들어간다(구조만 못 고친다).

### 합의한 것 (소유자, 2026-11-10)

1. **참조가 기본, 필요할 때만 따로 떼기.** 세트를 가져다 쓰는 곳은 원본과 이어져 있다 — 원본을 고치면 다 바뀐다. *"마야든 뭐든 그렇게 묶여 있는 이유가 있다."*
2. **"부분적으로" — 최종 형태는 조립이다(소유자: "최종적으로 (라) 방식이 되어야 한다").** 차는 차대로 "달린다"를 가진 세트이고, 화면 이동은 그것들을 품어 시간에 늘어놓는다.
   차를 고치면 차를 품은 모든 세트가 바뀐다. 구조는 §7. 그 전 단계(S1~S6)의 "품는 것이 없는 세트"는 조립 구조에서도 그대로 유효하다(구성원이 제 노드뿐인 세트).
   세트 안에서 오브젝트를 하나씩 따로 보고 돌려 보는 것(솔로·끄기)은 그와 별개로 S3에서 넣는다.
3. **키는 두 층.** 세트 안의 움직임은 세트의 애니메이션에 속한다(이름으로 부르고, 어디서 쓰든 같다). 세트를 장면에 놓고 언제 무엇을 틀지는 클립에 속한다. 지금의 모션/클립 구분 그대로.

## 2. 작업 방식 — 배치 모드와 애니메이션 모드 (스파인의 Setup / Animate)

세트를 열면 뷰포트에는 그 세트만 선다(캐릭터에 붙는 세트면 붙을 캐릭터의 자리표시와 함께).

| | 배치 | 애니메이션 |
|---|---|---|
| 뷰포트에서 끌면 | 오브젝트의 **가만히 선 자세**(자리·크기·회전)가 바뀐다 = 구조 | 고른 애니메이션에 **키**가 놓인다(Auto Key) |
| 하이어아키 | 오브젝트 더하기(그림 · 색 · 글자) · 지우기 · 이름 · 부모 바꾸기 · 순서 | 오브젝트 고르기 · 솔로 · 끄기 |
| 그림 | PNG를 끌어다 놓으면 그 자리에 그림 오브젝트가 선다 | — |
| 그래프·도프 시트 | 비어 있다 | 고른 애니메이션 |

- 지금의 리그 편집기(숫자 칸)·조각 끌어 놓기·"이모지" 탭의 구간 고치기는 이 두 모드의 **일부를 이모지 안에서만** 한 것이다. 기능은 살리고 자리를 옮긴다.
- 스킨이 여럿인 세트(이모지)에서 "이 스킨에서만 조각이 여기에 놓인다"는 스킨의 놓임으로 남는다(`PLAN-parts.md` §13). 스킨이 하나인 세트(화면 이동)는 오브젝트의 자세만으로 된다.

## 3. 단계

한 번에 하나, 단계마다 기존 예시(`examples/emoji`)가 계속 열리고 돌아야 한다.

| 단계 | 무엇 | 끝나면 |
|---|---|---|
| **S1. 세트를 연다** | 왼쪽에 **세트 목록**(툴이 정의한 리그들). 고르면 뷰포트·하이어아키가 그 세트만 보인다. 하이어아키에서 오브젝트 더하기·지우기·이름·부모·순서(명령은 이미 있다 — `PLAN-parts.md` §12) | "이모지" 탭 구석의 리그 편집기가 필요 없어진다 |
| **S2. 배치 모드** | 뷰포트에서 끌어 자리·크기·회전을 잡는다(가만히 선 자세). 노드에 회전·배율을 둔다. PNG를 끌어다 놓으면 그림 오브젝트 | 숫자 칸 없이 세트의 모양을 짓는다 |
| **S3. 애니메이션 모드** | 세트의 애니메이션 목록(그 rigKind의 모션). 고르면 지금의 그래프·기즈모·Auto Key 그대로. 오브젝트 솔로·끄기 | 세트 하나를 열어 그 안에서 구조와 움직임을 다 만든다 |
| **S4. 색 사각형** | 노드 종류 "색"(색 · 불투명도). 런타임 규약에 더한다 | 화면 이동·날짜 소개의 패널 |
| **S5. 연출** | `EmojiAsset` → 연출: 서는 곳 = 캐릭터의 기준점 / 화면 전체. "이모지" 탭 → "연출". 저장된 문서의 `emojis`는 그대로 읽는다 | 이모지가 연출의 한 종류가 된다 |
| **S6. 화면 이동을 실제로 만든다** | 참고 영상의 화면 이동을 세트로(그림이 없으면 색 사각형으로 뼈대) — 만들면서 걸리는 곳을 고친다 | 범용 구조가 이모지 밖에서 선다 |
| **S7. 글자와 받는 값** | 노드 종류 "글자", 연출이 부를 때 받는 값(날짜·이름) | 날짜 소개 |
| **S8. 초상 자리** | 노드 종류 "초상 자리"(어느 캐릭터의 초상을 끼울지 받는다) | 캐릭터 소개 |
| **S9. 세트가 세트를 품는다** | 구성원 = 제 노드 또는 다른 세트의 인스턴스(참조). 하이어아키에 펼쳐 보인다. 순환 검사 · 이름 따라 바꾸기 | 차 · 해가 따로 세트 |
| **S10. 재생 블록** | 애니메이션이 "품은 세트의 애니메이션을 언제 튼다"를 담는다 — 클립의 타임라인·블록 끄기·안에서 고치기·따로 떼기를 다시 쓴다 | 화면 이동 = 조립 |
| **S11. 구워서 내보내기** | 품은 것을 다 펼쳐 "리그 하나 + 모션 하나"로(§7의 A) | 런타임은 그대로 |

**S1 완료(2026-11-10).** 왼쪽 맨 위에 세트 목록(새 세트 · 세트 삭제 · 닫기 · rigs.json…). 고르면 `ViewportView.SetView`가 켜져 뷰포트의 씬이 **그 세트 하나가 선 보기 전용 씬**이 된다
(문서의 씬은 안 건드린다 — 오브젝트 id `set`). 하이어아키는 그 씬으로 서므로 세트의 오브젝트들이 그대로 보이고, 우클릭으로 더하기(묶음 · 그림)·순서·부모·지우기.
오브젝트를 고르면 "씬" 탭 맨 위의 **세트의 오브젝트** 칸(이름 · 부모 · X · Y · 너비 · 높이 · 그림 · 불투명도)이 그것을 본다. 그 세트의 모션을 고르면 세트가 연기하고,
클립·연출·다른 리그의 모션을 고르면 세트를 떠난다. "이모지" 탭의 리그 칸(조각 수 · 노드 목록)은 없앴다(`MainWindow.Rigs.cs` → `MainWindow.Sets.cs`).
거친 곳: 세트 보기에서도 하이어아키에 빈 무대·층 폴더가 보이고 "씬" 탭 아래에 씬의 칸이 잠긴 채 남는다 · 세트가 무대 한가운데에 작게 선다(보기 맞춤이 없다) ·
스킨은 그 세트의 첫 스킨을 입는다(고르는 것은 S2).

순서(소유자 승인): S1~S6을 먼저(한 덩어리로 실제 연출을 하나 만든다), 조립(S9~S11)은 그 뒤. S7·S8은 필요에 따라 앞뒤로.

S1~S3이 **작업 순서를 바로잡는** 단계이고(새 데이터가 거의 없다), S4부터가 새 기능이다.

## 5. 열어 둔 것

1. (조립은 §7로 정해졌다.)
2. **대본이 연출이 끝나길 기다리는가**(K6의 그 질문). 화면 이동은 "다 덮였다"에서 장면을 바꿔야 하니 이벤트 키와 함께 답이 필요하다.
3. **글자.** 런타임의 글꼴·크기·색 규약을 모른다 — 툴의 미리보기는 어림이다(S7에서).
4. **채도 빼기.** 캐릭터 소개 영상은 배경의 채도가 빠진다 — 지금 구조로는 "어둡게 덮기"까지만 된다.
5. **가림(마스크).** 참고 영상 셋은 색 사각형을 기울여 닦는 것으로 된다. 진짜 가림이 필요한 연출이 나오면.
6. **캐릭터 리그도 세트 목록에 넣는가.** 구조를 못 고칠 뿐 같은 것이다 — S3에서 정한다.

## 6. 하지 않는 것

- 빠르기·세기 인자(소유자: "필요 없다").
- 런타임 규약의 뼈대(모션은 rigKind의 것)를 바꾸는 것 — 세트 = rigKind로 그대로 간다.

## 7. 최종 형태 — 조립 (소유자, 2026-11-10)

**세트가 다른 세트를 품고, 세트의 애니메이션이 "품은 세트의 애니메이션을 언제 튼다"를 담는다.**

```
화면이동 (세트)                       화면이동 · 등장 (애니메이션)
 ├ 배경막      제 노드(색)              배경막    ●───────●            키
 ├ 건물_뒤     제 노드(그림)            차        [ 달린다 ]           재생 블록
 ├ 해          → '해' 세트               해           [ 뜬다 ][ 뜬다 ]  재생 블록(반복)
 └ 차          → '차' 세트               차(통째)   ●──────────●       키 — 화면을 가로지른다
```

- **구성원**: 제 노드(그림 · 색 · 글자) 또는 다른 세트의 인스턴스(참조). 자기 자신을 품는 순환은 막는다.
- **애니메이션**: 키(제 노드 + 품은 세트를 통째로 옮기는 값) + 재생 블록(구성원 · 그 세트의 애니메이션 · 시각 · 반복).
- 이것은 **클립과 같은 꼴**이다 — 세트의 애니메이션은 "세트 안의 작은 클립"이다. 길게 보면 장면·클립은 "무대라는 가장 바깥 세트와 그 애니메이션"이 된다(지금 합치지는 않는다).
- **참조가 기본**: 품은 세트의 안쪽을 고치면 원본이 바뀐다("N곳에서 쓰인다"가 뜬다). 필요할 때만 따로 떼기.
- **안으로 들어가 고치기**: 바깥 세트를 보는 채로 안쪽을 고친다 — 클립 안에서 블록을 고치던 그 방식.

**내보내기는 A — 구워서 한 덩어리로(소유자 승인).** 툴 안에서는 조립이지만 산출물은 품은 것을 다 펼친 "리그 하나 + 모션 하나"다. 런타임은 지금 그대로(모션 하나 재생).
원본을 고치면 툴이 그것을 품은 세트를 다 다시 굽는다. 클립 굽기(`ClipBake`)의 계산을 다시 쓴다.
- 한계: 품은 세트가 끝없이 되풀이되는 애니메이션(머묾)을 틀 때 바깥의 되풀이와 주기가 안 맞으면 구운 결과가 길어지거나 이음매가 튄다 — 검증이 알린다.
- "부를 때마다 조각의 타이밍이 달라져야 한다"가 생기면 그때 B(조립 그대로 내보내고 런타임이 재생기를 갖는다)로.
